【核心思路】
──────────────────────────────────────────────────────────────────────────────
  通用模板引擎（后端公共服务层）
      ↓ 所有模块统一调用
  各业务模块（薪酬管理、人事管理、报表管理等）
      ↓ 嵌入 TemplateOperator 组件
  每个模块拥有自己的专属模板，操作界面统一，互不干扰

  系统管理 > 通用模板系统 → 精简为"模板管理中心"（只做模板导入、配置、管理）
  各业务模块 → 嵌入"模板操作组件"（只做填报、预览、导出）

================================================================================
一、现状分析
================================================================================

  当前问题：
  1. UniversalTemplateSystem.vue（2151行）是一个"大而全"的单体组件
     - 模板列表 + 导入 + 删除 + 字段映射 + 填报 + 预览 + 导出 全在一个文件
     - 无法被其他模块复用
  2. PerformancePayApproval.vue（744行）是另一套独立代码
     - 调用 /api/performance-pay-approval/ 专用API
     - 后端 performance_pay_routes.py（1023行）有硬编码的数据模型
     - 功能与通用模板系统重复
  3. 两套代码都在处理"义务教育学校教职工绩效工资审批表"
     - 维护成本高，界面不统一，不符合配置驱动原则

四、组件拆分详细设计
================================================================================

  【4.1 TemplateOperator.vue —— 可复用模板操作组件】
  ───────────────────────────────────────────────────────────────
  位置：frontend/src/components/template/TemplateOperator.vue

  功能定位：被各业务模块嵌入使用，提供模板的"填报、预览、导出"操作
  不包含：模板列表、导入、删除、字段映射配置（这些归 TemplateManager）

  Props 接口：
    templateId: string      // 必填，模板标识（如 "performance_pay_approval"）
    moduleName: string      // 可选，模块名称（用于页面标题和保存路径区分）
    showTitle: boolean      // 可选，是否显示标题栏，默认 true

  包含的功能模块（从 UniversalTemplateSystem.vue 中提取）：
    □ 模板预览（点击预览按钮 → 弹出预览对话框，用 Luckysheet 渲染）
    □ 填报对话框（fillDialogVisible）
      - 年月选择（单位汇总表类型）
      - 职工查询（个人表类型，支持身份证号/姓名搜索）
      - 统计范围设置（scopeDialog）
      - 填报口径设置（criteriaDialog）
      - 确认填报 → 调用 /api/universal-template/fill
      - 填报结果展示（HTML 渲染）
      - 备注编辑
    □ 导出功能
      - 导出 Excel 格式
      - 导出 Word 格式（docx 模板）
      - 导出 PDF 格式
      - 打印功能
    □ 保存功能
      - 保存已填报数据
      - 查看已保存文件列表
      - 从已保存文件加载

  调用的 API（全部走通用模板引擎）：
    GET  /api/universal-template/config/{templateId}       → 获取模板配置
    GET  /api/universal-template/preview/{templateId}      → 预览模板
    POST /api/universal-template/fill                       → 填报数据
    POST /api/universal-template/save                       → 保存
    POST /api/universal-template/export                     → 导出
    GET  /api/universal-template/saved-files/{templateId}  → 已保存文件
    GET  /api/universal-template/search-employee            → 搜索职工
    GET  /api/universal-template/tags                       → 标签列表
    GET  /api/universal-template/remarks                    → 备注信息

七、数据依赖分析 —— 决定不能全删 performance_pay_routes.py
================================================================================

  旧 performance_pay_routes.py 共有 15 个端点，按依赖关系分为两类：

  ┌─────────────────────────────────────────────────────────────────────┐
  │ A 类：与"填报/保存/导出"重复的端点（6个）→ 可删除                    │
  ├─────────────────────────────────────────────────────────────────────┤
  │ GET  /template-metadata       → 只有 PerformancePayApproval 用       │
  │ GET  /current                 → 只有 PerformancePayApproval 用       │
  │ GET  /data/{year}/{month}     → 只有 PerformancePayApproval 用       │
  │ POST /save                    → 只有 PerformancePayApproval 用       │
  │ POST /load-from-database      → 只有 PerformancePayApproval 用       │
  │ POST /export /export-v2       → 只有 PerformancePayApproval 用       │
  └─────────────────────────────────────────────────────────────────────┘
  ┌─────────────────────────────────────────────────────────────────────┐
  │ B 类：被其他模块依赖的端点（8个）→ 不能删！                          │
  ├─────────────────────────────────────────────────────────────────────┤
  │ GET  /list                    → PerformancePayUpload 用              │
  │ GET  /download/{id}           → PerformancePayHistory 用             │
  │ GET  /download-pdf/{id}       → PerformancePayHistory 用             │
  │ POST /upload-scan             → PerformancePayUpload 用              │
  │ GET  /scans                   → PerformancePayUpload 用              │
  │ GET  /history                 → PerformancePayHistory 用             │
  │ GET  /yearly-summary          → PerformancePayStatistics 用          │
  │ GET  /statistics              → PerformancePayStatistics 用          │
  └─────────────────────────────────────────────────────────────────────┘

  另外，performance_pay_history_routes.py 独立读取数据：
    - 数据来源：data/performance_pay_approval/performance_pay_{year}_{month}.json
    - 读取字段：绩效人数合计、绩效工资合计、乡镇补贴合计 等（硬编码）
    - 存储路径与通用模板系统完全不同

  【两个系统的数据存储对比】
  ┌──────────────┬──────────────────────────────┬────────────────────────┐
  │              │ 旧系统                        │ 通用模板系统            │
  ├──────────────┼──────────────────────────────┼────────────────────────┤
  │ 存储路径      │ data/performance_pay_approval/│ exports/templates/     │
  │              │                              │ 已保存/                │
  │ 数据格式      │ JSON（硬编码字段名）           │ Excel + HTML 文件       │
  │ 文件命名      │ performance_pay_{年}_{月}.json│ {单位}{年月}义务教育... │
  │              │                              │ 校教职工绩效工资审批表  │
  │              │                              │ (...).xlsx             │
  │ 字段结构      │ 副处级人数、正科级人数...      │ 配置驱动（由模板决定）   │
  └──────────────┴──────────────────────────────┴────────────────────────┘

  结论：切换模板引擎后，历史/统计/上传模块读不到数据。必须分两阶段解决。

十三、风险评估与回滚方案
================================================================================

  【风险点】
  1. TemplateOperator 从 UniversalTemplateSystem 拆分时可能遗漏依赖
     → 缓解：保留 UniversalTemplateSystem.vue 备份，逐步拆分
  2. 模板在通用模板系统中可能配置不完整
     → 缓解：在第2步中确认模板配置
  3. 旧路由 /performance/pay-approval 可能被其他地方硬编码引用
     → 缓解：全局搜索确认无残留引用
  4. 兼容写入的 JSON 字段名与旧系统不完全一致
     → 缓解：从 filled_config 中提取时做好字段映射
  5. 第二阶段改造后历史数据丢失
     → 缓解：先备份旧数据目录，确认新系统正常后再删除

  【回滚方案】
  第一阶段回滚：
  1. 恢复所有备份文件
  2. 删除新增的 TemplateOperator.vue、TemplateManager.vue、
     SalaryPerformanceApproval.vue
  3. 恢复 UniversalTemplateSystem.vue
  4. 恢复 navigation.json、router/index.ts、main.py
  5. 恢复 performance_pay_routes.py（全量，非精简版）
  6. 重启服务器

  第二阶段回滚：
  1. 恢复 performance_pay_history_routes.py 备份
  2. 恢复 performance_pay_routes.py 中 B 类端点的原始逻辑
  3. 恢复 universal_template_routes.py 中的兼容写入代码
  4. 从备份恢复 data/performance_pay_approval/ 目录
  5. 重启服务器

十四、与其他模块的潜在扩展
================================================================================

  完成本次拆分后，其他模块接入模板只需：

  1. 在通用模板系统中导入该模块所需的 Excel 模板
  2. 配置好字段映射
  3. 在业务模块页面中写一行代码：
     <TemplateOperator template-id="xxx" module-name="xxx" />

  例如：
  - 人事管理 > 退休呈报：
    <TemplateOperator template-id="retirement_report" module-name="人事管理" />

  - 报表管理 > 退休测算：
    <TemplateOperator template-id="retirement_estimate" module-name="报表管理" />

  未来新增任何需要模板的业务模块，零后端代码，只需配置模板 + 一行组件引用。
