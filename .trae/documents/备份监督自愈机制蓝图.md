# 备份与推送信息独立监督自愈机制 — 实现蓝图

## 一、Context（背景与必要性）

### 问题根源
当前系统的"自动备份+飞书推送"链路存在致命单点：**所有环节都依赖后端进程**。
- APScheduler调度器在后端进程内运行 → 后端挂 → 调度器挂 → 备份挂
- 飞书通知服务在后端进程内 → 后端挂 → 通知也发不出
- 历史教训：apscheduler模块丢失导致**连续7天没备份无人察觉**

### 用户明确诉求
> "必须有什么东西保证备份服务和推送信息能够自动运行，检查备份和推送是否运行，如果没有运行，应该有相应的处理，保证和促使备份和推送运行。没有监督，没有绝对的保证，数据安全就存在重大问题。"

### 目标
建立**独立于后端进程的监督者**，具备：
1. **多层探测**：后端存活 / 调度器状态 / 备份时效 / 推送有效性
2. **自愈能力**：发现问题后能自动重启服务、触发补偿备份、降级告警
3. **独立告警通道**：监督脚本自带飞书webhook，后端挂了也能发出告警
4. **监督的监督**：Windows任务计划程序定时唤醒监督脚本，避免监督脚本本身失效

```
                              ▼

                   读 db_backup_status.json

                   └─webhook也空→写 ALERT_FALLBACK.txt
                              │

```

### 自愈动作矩阵

| 故障 | 自愈动作（首选） | 自愈失败降级 |
|------|--------------|-----------|
| 后端挂 | `subprocess.Popen(["pythonw","d:\\erp_fifteen\\start_servers.py"])` 重启 | 独立webhook告警 |
| 调度器挂（后端在） | 重启整个后端（间接重启调度器，后端启动事件会触发`_check_and_compensate_backup()`） | webhook告警 |
| 备份超时（>26h） | 调用 `POST http://127.0.0.1:8000/api/backup-config/run` 触发备份 | webhook告警 |
| 备份连续失败≥2次 | webhook告警+附带最近一次失败详情 | 本地告警文件 |
| 飞书推送失败 | 用独立webhook补发告警 | 本地告警文件 |

## 四、API设计（不新增后端API，复用现有）

**核心原则**：监督脚本优先**直读JSON状态文件**，避免新增后端API（严格遵守零修改原则）。

| 探测/动作 | 方式 | 路径/文件 |
|---------|------|---------|
| 后端存活 | HTTP GET | `http://127.0.0.1:8000/docs` |
| 调度器状态 | HTTP GET（已存在） | `/api/backup-config/scheduler-status` |
| 备份状态 | 直读JSON文件 | `d:\erp_fifteen\tp_education_system\backend\config\db_backup_status.json` |
| 触发补偿备份 | HTTP POST（已存在） | `/api/backup-config/run` |
| 重启后端 | `subprocess.Popen` | 直接启动 `d:\erp_fifteen\start_servers.py` |
| 发送告警 | `requests.post` | 直POST飞书webhook，不经后端 |

**不新增任何后端API**。调度器挂了通过重启后端间接重启（后端main.py的startup事件会自动调用 `start_scheduler()` 和 `_check_and_compensate_backup()`）。

## 六、关键实现要点

### 1. 后端存活检测（三重保险）
- **端口探测**：`socket.connect_ex(("127.0.0.1", 8000)) == 0`
- **HTTP健康检查**：`requests.get("http://127.0.0.1:8000/docs", timeout=10).status_code == 200`
- **PID文件检查**：读`backend.pid`，用`os.kill(pid, 0)`判进程存活
- 任一失败即判后端挂

### 2. 重启后端（不弹黑窗、不阻塞）
```python
import subprocess
startupinfo = subprocess.STARTUPINFO()
startupinfo.dwFlags |= subprocess.STARTF_USESHOWWINDOW  # 隐藏窗口
proc = subprocess.Popen(
    ["pythonw", "d:\\erp_fifteen\\start_servers.py"],
    cwd="d:\\erp_fifteen",
    startupinfo=startupinfo,
    creationflags=0x00000008  # DETACHED_PROCESS，完全脱离父进程
)
# 写新PID
with open("state/backend.pid", "w") as f:
    f.write(str(proc.pid))
# 等待30秒再次健康检查
time.sleep(30)
```

### 3. 防重复启动监督脚本（PID锁）
```python
# 监督脚本启动时检查 supervisor.pid
# 若PID存活→说明上一轮监督还在运行（异常）→写告警退出
# 若PID不存在→写入当前PID，继续运行
```

### 4. 读备份状态（直读JSON，不依赖后端）
```python
import json
status_path = "d:\\erp_fifteen\\tp_education_system\\backend\\config\\db_backup_status.json"
with open(status_path, "r", encoding="utf-8") as f:
    status = json.load(f)
# last_backup_time / last_backup_success / consecutive_failures
# last_notification.success
```

### 5. 独立飞书告警（直POST，不依赖后端）
```python
import requests
def send_alert(webhook_url, msg):
    if not webhook_url:
        # 降级：写本地告警文件
        with open("state/ALERT_FALLBACK.txt", "a", encoding="utf-8") as f:
            f.write(f"[{datetime.now()}] {msg}\n")
        return False
    body = {"msg_type": "text", "content": {"text": msg}}
    for i in range(3):
        try:
            resp = requests.post(webhook_url, json=body, timeout=10)
            if resp.json().get("code") == 0:
                return True
        except Exception:
            time.sleep(5)
    return False
```

### 6. 告警静默期（避免30分钟内重复告警同一故障）
- 状态记在 `state/alert_state.json`：`{"故障类型": "后端挂", "首次告警时间": "2026-09-29 10:00:00", "已告警次数": 1}`
- 30分钟内同一故障类型不重复告警

## 七、安装与卸载脚本（PowerShell）

### install_supervisor_task.ps1
```powershell
$taskName = "ERP_Supervisor_Watchdog"
$supervisorScript = "d:\erp_fifteen\supervisor\supervisor.py"
$pythonExe = "pythonw.exe"  # 无窗口运行
$action = New-ScheduledTaskAction -Execute $pythonExe -Argument $supervisorScript
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(1) `
    -RepetitionInterval (New-TimeSpan -Minutes 30) `
    -RepetitionDuration ([TimeSpan]::MaxValue)
$settings = New-ScheduledTaskSettingsSet `
    -AllowStartIfOnBatteries `
    -DontStopIfGoingOnBatteries `
    -StartWhenAvailable `
    -ExecutionTimeLimit (New-TimeSpan -Minutes 5)
Register-ScheduledTask -TaskName $taskName -Action $action `
    -Trigger $trigger -Settings $settings -Force
```

### uninstall_supervisor_task.ps1
```powershell
Unregister-ScheduledTask -TaskName "ERP_Supervisor_Watchdog" -Confirm:$false
```

## 九、待用户决策事项

### 决策1：是否同意此方案？
若同意，将按上述蓝图实施。

### 决策2：监督脚本运行间隔
- 默认30分钟（推荐）
- 可选15分钟（更及时但CPU开销略大）
- 可选60分钟（更省资源但响应慢）

### 决策3：独立飞书webhook URL
需要用户配置一个飞书群机器人webhook URL，用于监督脚本发送告警。
- 该webhook可指向与现有应用通知相同的飞书群
- 配置后填入 `supervisor_config.json` 的 `独立飞书webhook.告警webhook` 字段
- 未配置则降级为本地告警文件（功能仍可用，但用户感知慢）
